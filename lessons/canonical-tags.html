LESSON 15

Canonical Tags

Bro, sometimes the same webpage can be accessible through multiple URLs. Search engines may see these as separate URLs, even when the content is identical or very similar. A canonical tag helps indicate which URL should be treated as the preferred version.

1. What Is a Canonical Tag?

A canonical tag is an HTML element placed inside the <head> section of a webpage. It tells search engines which URL is the preferred version when duplicate or similar pages exist.

Simple definition: A canonical tag suggests the main URL that search engines should use for a page.

2. Why Do We Need Canonical Tags?

Imagine your website has a product page that can be opened using different URLs because of tracking parameters or filters.

For example, these URLs might show the same product:

  • /products/shirt
  • /products/shirt?source=home
  • /products/shirt?campaign=sale

Search engines may discover all three URLs. If they contain the same main content, you can indicate that /products/shirt is your preferred URL.

3. Canonical Tag Syntax

A canonical tag looks like this:

<head>
  <link rel="canonical" href="https://your-own-domain.com/products/shirt" />
</head>

Replace the example domain and path with the actual preferred URL from your own website. The canonical URL should be a valid URL that you control.

4. How Does It Work?

  1. A search engine discovers multiple URLs with similar content.
  2. Your canonical tag identifies the URL you prefer.
  3. The search engine considers that signal along with other signals.
  4. The search engine decides which URL is most appropriate to index.

Important: A canonical tag is a hint, not a strict command. Search engines may choose a different canonical URL when other signals suggest it is more appropriate.

5. Self-Referencing Canonical Tags

A self-referencing canonical tag points to the preferred URL of the page on which it appears.

For example, if your preferred product URL is /products/shirt, that page can contain a canonical tag pointing to its own preferred URL.

This can help reinforce which URL you want search engines to consider canonical, although it does not guarantee that the URL will be selected.

6. Canonical Tags vs. Redirects

  • Canonical tag: Suggests the preferred URL while allowing the other URL to remain accessible.
  • 301 redirect: Sends visitors and search engines from one URL to another permanently.

If an old page has permanently moved and should no longer be accessed through its old URL, a redirect is usually more appropriate than relying only on a canonical tag.

7. Common Canonical Tag Mistakes

  • Pointing the canonical tag to the wrong page.
  • Using a URL that does not exist or returns an error.
  • Pointing unrelated pages to the same canonical URL.
  • Using inconsistent canonical URLs in different SEO signals.
  • Assuming a canonical tag guarantees indexing.
  • Accidentally using a development or testing URL as the canonical URL.

8. Canonical Tags and Your HTML Project

Bro, suppose your website has a service page that can be reached through more than one URL. First, decide which URL should be the preferred one. Then place the canonical tag inside that page's <head> section.

Always use your own correct domain and the preferred page URL. Don't copy an example domain into your real website.

9. Quick Revision

  • Canonical tags help identify a preferred URL.
  • They are useful for duplicate or very similar pages.
  • They belong inside the HTML <head> section.
  • They are hints, not guaranteed instructions.
  • Use redirects when a page has permanently moved.

10. Practice Task

Imagine your website has a product page accessible through these URLs:

  • /products/phone
  • /products/phone?source=home
  • /products/phone?campaign=offer

Answer these questions:

  1. Which URL would you choose as the preferred URL?
  2. Where should you place the canonical tag in the HTML document?
  3. Does a canonical tag guarantee that Google will index your preferred URL?
